# FLUX 3 Image Klein Studio

Gradio-интерфейс ко всем возможностям [FLUX 3 Image Klein](https://huggingface.co/black-forest-labs/flux-3-image-klein) —
открытой 5.6B-модели Black Forest Labs (релиз 15 октября 2026). Рассчитан на одну RTX 3090/4090 (24 GB) в облаке.

| Вкладка | Что делает |
|---|---|
| 🎨 Генерация | Текст → изображение: 15 пропорций и тиры площади как в BFL API (768² / 1K / 1.5K / 2K / 4K) или свой размер кратно 16 |
| 🖌️ Редактирование | Правка по инструкции и композиция из 1–10 референсов («the first image», «the second image»…); размер как у №N, по пропорциям или вручную |
| ▣ Раскладка | Раскладка боксами: протянуть по холсту — бокс (и внутри другого), за подпись — переместить, за маркеры — размер, клик по перекрытию — бокс под ним, Delete / ✕ — удалить, Ctrl+Z — отменить; у каждого id и описание; апсемплер пишет сцену вокруг них |
| 🎯 Правка боксами | Точечная правка поверх референса тем же редактором, что раскладка: ➕ новый / заменить, ↔ перенести (рамка «куда» со стрелкой), 📌 оставить, ✖ удалить; действие меняется у готового бокса |
| 🕘 История | Все генерации из `outputs/` с параметрами; вернуть картинку в референсы или описание+seed в генерацию |

Общее — в боковой панели: модель **Distilled** (16 шагов, без CFG) или **Base** (50 шагов, CFG, negative prompt),
шаги, seed, число картинок, длина описания апсемплера, **LoRA** (несколько, с весами).

**✨ Апсемплер промптов** — официальная модель BFL [flux-3-image-klein-pup](https://huggingface.co/black-forest-labs/flux-3-image-klein-pup)
(9B, Qwen3.5-9B). BFL прямо просит не использовать Klein без него: модель обучена на подробных описаниях сцены,
короткий промпт «как есть» даёт заметно более слабый результат. Апсемплер видит референсы и сохраняет боксы.
Галочка по умолчанию снята, потому что апсемплер добавляет ~15–18 с к каждому новому промпту
(`KLEIN_UPSAMPLE_DEFAULT=1` — включена); при коротком промпте без него под результатом появится предупреждение.
Описание, ушедшее в модель, показывается под результатом; «✨ Только переписать» кладёт его в поле промпта, чтобы
поправить руками и перебирать seed без повторного переписывания. Одинаковые запросы кэшируются.

**Текстовый энкодер** по умолчанию — `DreamFast/Qwen3-VL-4b-Heretic`: тот же Qwen3-VL-4B-Instruct, что в Klein,
обработанный [Heretic](https://github.com/p-e-w/heretic) (из скрытых состояний убрано направление «отказа»). Архитектура и
токенизатор те же; на обычных промптах картинки практически совпадают с оригинальным энкодером, включая надписи
(сравнение на одном seed). Вернуть оригинальный — `KLEIN_TEXT_ENCODER_ID=""`. Какой энкодер использован, записано в JSON
рядом с картинкой.

**👥 Очередь на несколько пользователей.** Видеокарта одна, пользователей много: все задачи со всех вкладок идут
через общую очередь. Под кнопкой видно место в очереди и примерное время до старта, потом — шаги генерации;
в шапке — что сейчас делает видеокарта и когда освободится. «✖» отменяет задачу и в очереди, и посреди генерации
(на следующем шаге). У пользователя не больше 2 задач одновременно, история у каждого своя.

Под каждым результатом: «↪ В референсы» (итеративная правка: результат → следующий шаг) и «↪ Описание в промпт».
Каждая генерация сохраняется в `outputs/` — PNG с параметрами в метаданных и JSON рядом.

## Файлы

```
app.py         интерфейс и обработчики вкладок
backend.py     KleinBackend (Diffusers ModularPipeline, CUDA) и MockBackend (заглушка), размеры, LoRA
upsampler.py   апсемплер промптов: локально, через vLLM-сервер или заглушка; кэш описаний
scheduler.py   очередь задач к видеокарте: позиции, оценка времени, группировка по фазам, лимиты, отмена
vram.py        видеопамять: веса в закреплённой RAM, на карту — по требованию, запас под активации по запросу
box_editor.py  редактор раскладки в браузере (gr.HTML + JS): рисование, перетаскивание, удаление, отмена
layout.py      боксы: формат пайплайна (0–1) и модели (0–1000), таблица, отрисовка на холсте
setup.sh       установка «в одну команду» на GPU-сервер (Vast.ai или любая Linux-машина)
```

## Быстрая установка на GPU-сервер

Веса Klein закрыты лицензией (FLUX Kommunity License, одобряется автоматически): один раз нажмите
«Agree» на странице [flux-3-image-klein](https://huggingface.co/black-forest-labs/flux-3-image-klein)
(и [flux-3-image-klein-base](https://huggingface.co/black-forest-labs/flux-3-image-klein-base), если нужен Base)
и создайте [токен](https://huggingface.co/settings/tokens) с правом чтения.

```bash
git clone https://github.com/GrafikXxxxxxxYyyyyyyyyyy/flux-3-image-klein-studio.git
cd flux-3-image-klein-studio && HF_TOKEN=hf_... bash setup.sh
```

`setup.sh` ставит зависимости, качает веса (~39 GB: Distilled ~20 GB + апсемплер ~19 GB; `KLEIN_BASE=1` — ещё ~11 GB),
запускает приложение и открывает публичную ссылку через Cloudflare quick tunnel (**без пароля**: GPU доступен любому,
у кого есть ссылка; `KLEIN_PUBLIC=0` — без ссылки). В конце печатает адрес. На Vast.ai приложение и туннель ставятся
сервисами supervisor (`klein-studio`, `klein-studio-tunnel`), на других машинах — фоновыми процессами с логами в `logs/`.
Повторный запуск безопасен: обновляет код и перезапускает приложение, ссылка остаётся прежней. Опции — в шапке `setup.sh`.

## Запуск вручную

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
hf auth login
python app.py --host 127.0.0.1 --port 7860
```

Открыть с вашей машины — через SSH-туннель (безопаснее публичной ссылки): `ssh -L 7860:localhost:7860 user@server`,
дальше http://localhost:7860. Альтернатива — `python app.py --share --auth логин:пароль`
(публичная ссылка `*.gradio.live`; без `--auth` GPU доступен любому, у кого есть ссылка).

## Память и железо

Веса в bf16: трансформер 11 GB, текстовый энкодер Qwen3-VL-4B 8 GB, апсемплер 19 GB, VAE 0.3 GB — всего ~39 GB
(+11 GB трансформер Base). Энкодер и VAE у Distilled и Base общие и грузятся один раз.

- **≥ 48 GB VRAM** (A6000, L40S, A100, H100) — всё помещается на карту сразу.
- **24 GB (RTX 3090/4090)** — модели живут в закреплённой (pinned) RAM, на карту попадает то, что нужно сейчас
  (`vram.py`). На 1 MP трансформер и энкодер остаются на карте вместе; апсемплер на время работы вытесняет обоих,
  и возвращаются они за ~1.5 с (копирование из закреплённой памяти идёт ~13 GB/s даже на PCIe 4.0 x8).
  Запас под активации считается по запросу (размер, число картинок, референсы), поэтому 2K–4K и 10 референсов
  не падают в OOM, а на всякий случай есть повтор с VAE тайлами.
- **RAM** — от 64 GB: Distilled, энкодер и апсемплер занимают ~36 GB закреплённой памяти (с Base — ~47 GB).
  Если RAM мало, `KLEIN_PIN_MEMORY=0` — обычная память, перекладывание медленнее.
- **Диск** — ~45 GB под веса.

Замеры на RTX 3090 (PCIe 4.0 x8), Distilled 1 MP, описание длиной ~250 слов:

| | 16 шагов | 8 шагов | 4 шага |
|---|---|---|---|
| описание готово (кэш, «Только переписать») | ~15 с | ~9 с | ~6 с |
| с апсемплером (он сам ~15–18 с) | ~34 с | ~27 с | ~24 с |

Шаг трансформера на 1 MP — ~0.77 с при 100 % загрузке карты; это потолок 3090 в bf16. Distilled — flow-map модель
и сама умеет 4–8 шагов без всяких LoRA: на фото 8 шагов почти неотличимы от 16, но надписи на картинке
(вывески, текст) на 16 шагах заметно чище. Референсы ужимаются как в коде BFL: один — до 4 MP, несколько — до 1 MP
каждый (Diffusers пропускает до 16 MP, и фото с телефона замедляло генерацию в разы).
Апсемплер (Qwen3.5) работает на ядрах `flash-linear-attention` и `causal-conv1d` — без них в разы медленнее.

## Очередь и много пользователей

Обработчики Gradio не трогают модель сами: они ставят задачу в `GpuScheduler` и асинхронно ждут её (поэтому
одновременно ждать могут сколько угодно пользователей, не занимая потоки). Видеокарту занимает один рабочий поток.

- **Группировка по фазам.** Задача проходит до двух фаз: апсемплер и генерация. На 24 GB они не помещаются вместе,
  и каждая смена — перекладывание ~19 GB между RAM и видеопамятью. Поэтому, пока апсемплер в видеопамяти, он
  переписывает промпты всех ожидающих подряд, затем подряд идут генерации (то же для Distilled/Base). Серия
  ограничена `KLEIN_PHASE_STREAK` задачами, дальше — самая старая задача, чтобы никто не ждал бесконечно.
  С апсемплером на отдельном сервере его фаза идёт параллельно с генерацией.
- **Кэш описаний.** Повтор того же запроса (другой seed, другой размер) не ставится в очередь к апсемплеру.
- **Лимиты.** Не больше `KLEIN_USER_MAX_JOBS` задач на пользователя (id браузера хранится в localStorage) и
  `KLEIN_QUEUE_MAX` в очереди всего — сверх этого пользователь видит понятную ошибку.
- **Отмена.** Кнопка «✖» или закрытая вкладка снимают задачу из очереди; идущая генерация останавливается на
  следующем шаге (хук на вызов трансформера), видеокарта сразу берёт следующую.
- **История** по умолчанию личная: каждый видит только свои картинки (`KLEIN_HISTORY=all` — общая лента).
- В логе приложения по строке на задачу: `[queue] #12 3f9a1c2e: done за 14.2 с (в очереди 5.1 с) · ждут: 3`.

Генерации идут строго по одной: параллельный запуск на одной карте не быстрее (GPU и так загружена полностью),
а памяти на 24 GB на две генерации не хватит.

## Отладка интерфейса без GPU (Mac)

```bash
uv venv .venv && VIRTUAL_ENV=.venv uv pip install -r requirements-mock.txt
KLEIN_MOCK=1 .venv/bin/python app.py
```

Вместо модели рисуются плейсхолдеры нужного размера с параметрами запроса, вместо апсемплера — заглушка: видно,
какой промпт, размер, боксы и референсы ушли бы в модель. Чтобы погонять очередь, замедлите заглушку:
`KLEIN_MOCK_STEP_SECONDS=0.5 KLEIN_MOCK_UPSAMPLE_SECONDS=2`.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|

| `KLEIN_TEXT_ENCODER_ID` | `DreamFast/Qwen3-VL-4b-Heretic` | текстовый энкодер: Qwen3-VL-4B-Instruct, обработанный [Heretic](https://github.com/p-e-w/heretic) (аблитерация отказов); пустое значение — оригинальный энкодер из репозитория Klein |
| `KLEIN_MODEL_ID` | `black-forest-labs/flux-3-image-klein` | Distilled: id на Hub или локальная папка |
| `KLEIN_BASE_MODEL_ID` | `black-forest-labs/flux-3-image-klein-base` | Base |
| `KLEIN_DEFAULT_MODEL` | `distilled` | какая модель грузится при старте (`base` — Base) |
| `KLEIN_PRELOAD_BASE` | — | `1` — грузить Base сразу, а не при первом выборе |
| `KLEIN_PIN_MEMORY` | `1` | `0` — веса в обычной RAM, а не закреплённой (если оперативной памяти мало); перекладывание моделей медленнее |
| `KLEIN_MEMORY_MARGIN_GB` | `0.6` | запас видеопамяти сверх оценки активаций, под фрагментацию. Больше — реже OOM, чаще выгрузка энкодера |
| `KLEIN_FP8_STORAGE` | — | `1` — веса трансформера хранятся в FP8 (5.6 GB вместо 11), считаются в bf16; работает и на Ampere, качество чуть ниже |
| `KLEIN_UPSAMPLER` | `local` | `local` / `server` / `off` |
| `KLEIN_UPSAMPLER_ID` | `black-forest-labs/flux-3-image-klein-pup` | модель апсемплера |
| `KLEIN_UPSAMPLER_URL` | — | OpenAI-совместимый адрес, например `http://localhost:8100/v1` (включает `server`) |
| `KLEIN_UPSAMPLER_NAME` | = `KLEIN_UPSAMPLER_ID` | `served-model-name` на сервере |
| `KLEIN_OUTPUT_DIR` | `outputs` | куда сохранять результаты |
| `KLEIN_QUEUE_MAX` | `32` | сколько задач может ждать в очереди всего |
| `KLEIN_USER_MAX_JOBS` | `2` | сколько задач одновременно у одного пользователя (в очереди + в работе) |
| `KLEIN_PHASE_STREAK` | `6` | сколько задач подряд обрабатывать в одной фазе (апсемплер / генерация), прежде чем вернуться к самой старой |
| `KLEIN_UPSAMPLE_DEFAULT` | — | `1` — галочка «✨ Апсемплер» включена по умолчанию |
| `KLEIN_HISTORY` | `own` | `own` — каждый видит свою историю, `all` — общая лента всех генераций |

## Апсемплер на отдельном vLLM-сервере (необязательно)

Если есть вторая видеокарта, апсемплер быстрее и не вытесняет Klein из видеопамяти. В отдельном окружении:

```bash
pip install vllm
CUDA_VISIBLE_DEVICES=1 vllm serve black-forest-labs/flux-3-image-klein-pup --port 8100 \
    --max-model-len 8192 --limit-mm-per-prompt '{"image": 10}'
```

и запустить студию с `KLEIN_UPSAMPLER_URL=http://localhost:8100/v1`. Системные промпты, формат запроса, сэмплинг
(жадный, presence penalty 1.5 для текста) и сверка боксов — те же, что в коде BFL и в Diffusers.

## Боксы: формат

В интерфейсе бокс — `[y0, x0, y1, x1]` в долях кадра (0–1, начало в левом верхнем углу), так их принимает
пайплайн Diffusers. Модель читает их в конце промпта JSON-таблицей на холсте 0–1000:

```text
Hot-air balloons over a green valley <balloon_1> ... [{"id": "balloon_1", "bbox": [80, 60, 480, 380], "desc": "a red balloon"}]
```

Для правки строка ещё указывает источник: `"from": "target"` — новый элемент в `tgt_bbox`;
`"from": "ref_image_0"` — элемент первого референса, `src_bbox` — где он сейчас, `tgt_bbox` — где будет
(равные боксы — оставить на месте, `null` — удалить). С апсемплером всё это пишется само; без него студия
дописывает таблицу к вашему тексту, а `<id>` в тексте нужно поставить самим.
